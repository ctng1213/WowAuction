# Plan: AHledger as an additive source, kind-based precedence, the Data coverage card, the history backfill

Written for: the Opus session that orchestrates this batch in Claude Code on this repo, delegating the tasks tagged **Sonnet** to Sonnet subagents and doing the tasks tagged **Opus** itself. The user has approved the spec and the mockup; nothing below is open for redesign.

## 1. What is decided (do not re-litigate)

- **Additive only.** Nothing but the data-source layer and the Status page changes. The whole-plan snapshot `tests/fixtures/worlds/w1.expected.json` (WP1) must stay **byte-identical** through M19 and M21 (the W1 world has no AHledger rows); M20 adds the Status page's `coverage` field and nothing else.
- **Per (item, hour) the most granular dump wins:** kind order `book` (complete order books: your scans, AHF Premium books) > `hourly` (per-key hourly observations: AHF h1, AHledger `ahledger_h1` buckets) > `table` (per-item aggregate tables: the AHledger price table), then `local` first, then the config `rank` (`["ahf", "ahledger"]`), then unranked sources by name. The kind is derived from `src` in one table, `collect/provider.py` `SOURCE_KINDS`; analysis never names a source. The current-price rule stays newest-wins, `local` on ties. Volume is untouched.
- **AHledger's price table is the live source `ahledger`** (keyless, `If-None-Match`/ETag, 30-minute poll). Its `median, m7, m30, lo, hi, perDay` are **stored in `ahledger_rows` and used nowhere**. AHledger's own SavedVariables scan file is **not** read. The per-item history is the **backfill** (`ahledger_h1` hourly for 7 days, daily for 90 days, missing hours and days only).
- **`primary` defaults to `"ahledger"`** for the freshness pill and "prices newer"; AHF stays synced and ranked first for closes.
- **The coverage heatmap shades by fraction** (value ÷ possible, so 12 of 12 is as dark as 13 of 13), six steps; the per-source table and the counting rule are exactly as SPEC §3.5 and the mockup state. A partial scan never counts.
- **Attribution** is a term of AHledger's licence: "AHledger" linked to https://ahledger.com wherever its data is shown (Status line, coverage source row, item detail source mix, the top-bar pill when it is primary). Never present its data as our own scan.
- **No API key, no secrets.** If a key is ever added it follows the AHF key rules (env var, never logged, fixtures redacted).
- **Decided during execution (M20, Opus).** (1) The real Status page has no "Recent problems" list (its alerts are drawn first), so the coverage card sits after the summary cards and before the calibration section; SPEC §3.5 says so. (2) The item detail names no price source, so S19's attribution lands where a price source is named: the Gathering AH Price hover ("seen 26 h ago (AHledger)", no longer "AHledger scan …": a table is not a scan), its `price_source`/`price_url` row fields and a linked "prices from AHledger" segment on its freshness line. (3) Alerts about AHledger carry `url_label` ("AHledger") so the page links the name, not the bare URL (found in the headless render).
- **Decided during execution (M21, Opus).** (1) A `429` waits its `Retry-After` up to 300 s, as SPEC §2.3 and §5.2 say (this plan's 21.2 said 60 s; the spec wins); a longer one, or AHledger unreachable after the retries, pauses the backfill for an hour, then it resumes from the checkpoint (SPEC said only "ends the backfill for this run"). (2) The backfill lives in its own module, `collect/ahledger_backfill.py`, for size; it runs as a scheduler hook every 5 s doing 10 keys (about 4 s) per tick, so a stop is honoured within seconds. (3) Each key asks `7d` then `90d`; the checkpoint records the last key committed (its `range` is always `90d`). (4) The progress line is an info Status line (FM47's "without an alert" read as: no warning). (5) The client spaces AHledger requests 200 ms apart (`ApiClient(paced=True)`), shared by the poll and the backfill (SRC13).

Spec: `docs/SPEC.md` §2.2 (the one-close rule), §2.3 (AHledger), §3.2 (tables, schema 24), §3.5 Status, §3.6 config, §5.0/§5.2, §7 "AHledger and data coverage". Scenarios: `docs/SCENARIOS.md` rows SRC6–SRC16, S18–S20, FM43–FM47, D89–D96; all listed in `tests/pending_scenarios.txt`. Mockup: `docs/mockups/dashboard.html`, the Status page's "Data coverage" card and the market card's AHledger line.

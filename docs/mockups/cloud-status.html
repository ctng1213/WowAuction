Proposal: the cloud status page

Approved by the user, 2026-11-10 (the week picker added the same day; 12 blocks, not 13, at the spec merge). A static page, status.html, served by the summaries' CloudFront distribution next to status/<market>.json, which the analyzer rewrites at the end of every run (plan docs/plans/cloud-status.md). Every value and colour below is in that JSON, made and tested in Python (ahcloud/status.py). The page computes one thing itself: how old the JSON is (decision 5). All times are UTC, because the SLAs are UTC. The sample shows 14:30 UTC on Tue 10 Nov, viewed at 14:37.

The dashed value is the one number the browser computes: now minus written_ms. Everything else is fixed text from the JSON, as of 14:30. The ages under Freshness are as of that time, which the card header says.

The week picker (dashed; try it). It offers 7-day blocks ending today: the last 7 days (the default), then each 7 days before that: 12 blocks (84 days), inside the 90 days the summary's record of analysed hours reaches. Each option's label carries that week's verdict ("complete", "9 h missing"), so a bad week shows without opening it; ‹ goes back a week and › forward. The JSON holds all 13 weeks of cells as one character per hour (about 2 KB), plus each week's label and its missing-hours line, all made in Python: choosing a week only redraws. The picker stops at the first week with a snapshot; that week's hours before collection began are blank.

2. The thresholds behind the colours

Every hour collectedgreen 24/24 hours in the last 24 h and newest ≤ 75 min · amber 1–2 hours missing, or newest 75 min – 3 h · red newest > 3 h (alarm NoNewSnapshot)
Hourly pricesgreen ≤ 20 min behind the newest snapshot · amber 20 min – 3 h, or the last hourly run had no baseline · red > 3 h (alarm NoMarketSummary)
Daily analysisgreen today's published by 09:30 · amber late, before 12:00 · red none for 27 h (alarm NoDailyBaselines, tightened from 36 h)
No failed runsgreen 0 errors in 24 h, queue empty · amber a snapshot refused by the daily run (by design, FM74) · red any error alarm, or the queue not empty
Run time vs limitgreen < 66% of the function's timeout · amber 66–90% · red > 90% (new alarm: analyzer over 12 min)
The status itselfgreen ≤ 70 min old · amber 70 min – 3 h · red > 3 h. The limits come from the JSON; the browser only compares.

The headline is the worst colour among the SLAs and the status's own age. Its text names the worst one; with two or more ambers it reads "Running, N warnings".

4. What the page does not show

No bucket names, account id, ARNs, function names, log text or Blizzard credentials: the JSON is public, like the summaries (SEC row in the spec merge). No cost figures (decision 6). No per-item market data: that is the summary document's job. The CloudWatch dashboard (milestone H1) has the drill-down: per-function errors, invocations, throttles and durations, queue depth, metric bars and the warning log lines.
